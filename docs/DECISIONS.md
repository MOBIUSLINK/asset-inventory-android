# 已确认决策记录

| 决策 | 原因与约束 |
|---|---|
| 首版只支持 Android、完全离线、中文 | 适配现场环境，降低依赖与学习成本 |
| 当前公司放在顶部下拉菜单 | 公司是全局数据上下文，不属于任务管理 |
| 同公司可有多个进行中任务 | 实际盘点任务可能并行；页面只展示当前公司的任务 |
| 不同公司允许相同资产编号 | 编号唯一性只在公司范围内成立 |
| 区域二维码使用 `AREA:` 加稳定编号 | 二维码不写中文，App 显示区域名称 |
| 资产二维码使用 `ASSET:` 加编号 | 与区域码和传输码明确区分 |
| 扫码成功立即入库并播报完整编号 | 连续盘点以效率为先 |
| 语音队列只保留最新编号 | 新扫码中断旧播报，避免队列积压 |
| 当前区域重复不重复计数 | 同一资产不应在同一区域形成多个有效数量 |
| 跨区域重复由人工判断移动或编号冲突 | 不能默认认为都是编码错误 |
| 台账外编号允许录入 | 标记为新增待入账，不阻断现场工作 |
| 传输二维码保留“核对并导入” | 数据导入比普通资产扫码风险高 |
| 默认通过二维码面对面传输 | 文件发送/导入仍保留，便于飞书和 QQ 协作 |
| 文件后缀为 `.invtask`、`.invresult`、`.invbackup` | 名称可直接说明用途且避免歧义 |
| 完整备份始终包含全部公司 | 保证删除和恢复有完整安全底座；恢复范围可选择 |
| 删除、覆盖、恢复前创建保护性备份 | 优先保证数据可恢复 |
| 打印机为 NIIMBOT B3S_P，标签 T40×15 | 官方 SDK 随项目保存，现有标签布局以真机样张为准 |
| 图标必须与文字配合 | 降低首次使用的学习成本 |
| 返回始终遵循上一步 | 保持操作和思维连续性 |

新决策应追加记录，不应只保存在聊天中。若推翻旧决策，需注明日期、原因和影响范围。
