# 核心对象与数据规则

数据库文件为 `asset_inventory.db`，当前 schema version 为 `12`，启用外键约束。

## 对象关系

```text
公司 company
├─ 区域 area
├─ 台账导入 ledger_import
│  ├─ 台账资产 asset_ledger
│  └─ 导入异常 ledger_issue
└─ 盘点任务 inventory_task
   ├─ 任务区域 task_area（保存区域编号和名称快照）
   ├─ 工作交接 work_session
   └─ 扫码事件 scan_event
      └─ 异常照片 anomaly_photo
```

## 关键约束

- 公司使用稳定 UUID 标识；公司编号全局唯一，曾被其他公司使用过的旧编号不能重新占用。
- 区域编号在公司范围内唯一，允许不同公司使用相同区域编号。
- 台账资产主键为“公司 ID + 资产编号”，不同公司允许相同资产编号。
- 任务属于唯一公司；任务区域保存名称和编号快照，使历史任务不随区域改名而改变。
- 扫码事件使用唯一 `event_uuid`，结果包重复导入时据此去重。
- 记录保存任务、区域、资产编号、原始二维码、盘点人员、时间、来源设备和来源数据包。
- 撤销不直接抹除扫码事件，保存撤销时间、操作人和原因。
- 异常保存类型、说明、处理人、处理时间和照片路径。
- 公司修改和删除保留审计信息；任务、公司删除前创建完整 `.invbackup`。

## 二维码规则

- 资产：`ASSET:资产编号`。
- 区域：`AREA:区域编号`。
- 区域编号仅使用字母、数字、横线和下划线，不写入中文名称。
- 资产编号需要兼容历史实际数据，包括数字位数差异和因历史重复产生的 `-1` 后缀。
- 允许录入台账外编号，并标记为“新增待入账资产”。

## 文件格式

- `.invtask`：指定一个或多个区域的盘点任务包。
- `.invresult`：盘点结果包，合并时必须预览范围并依据事件 UUID 去重。
- `.invbackup`：始终包含全部公司的完整数据库与异常照片；恢复时可选择全部、单个公司或单个任务。

## 数据结构修改规则

- 不得删除旧数据后重建数据库来代替迁移。
- 增加或修改表结构必须升级数据库版本并实现 `onUpgrade`。
- 同步更新任务包、结果包、备份、Excel 导入导出与选择性恢复代码。
- 修改唯一约束前必须检查多公司、重复导入及历史编号兼容性。
